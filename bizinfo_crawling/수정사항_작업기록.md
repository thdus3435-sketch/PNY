# bizinfo_datalist.py 수정사항 작업 기록

## 1. 마감 공고 처리 방식

- 마감 공고는 삭제하지 않고 `숨김여부 = Y`로 처리한다.
- 삭제하지 않는 이유는 수집 이력, 중복 판단, 정기공고 매칭 이력, 재공고 비교를 유지하기 위해서다.
- 기본 조회에서는 `숨김여부 = Y`인 공고를 제외하고, 필요할 때 별도 필터로 확인하는 구조를 권장한다.

## 2. 접수상태 판정 변경

- `classify_status_from_apply_period()`에서 신청기간 종료 후 상태를 `확인필요`가 아니라 `마감`으로 반환하도록 정리했다.
- 신청기간이 없거나 날짜 파싱이 불가능한 경우는 기존처럼 `확인필요`로 둔다.

## 3. 기존 공고 숨김여부 보정

- `refresh_hidden_status_for_existing_notices(new_sheet)`를 통해 기존 `신규공고` 시트의 전체 행을 점검한다.
- 숨김 기준:
  - `접수상태`가 `마감` 또는 `종료`
  - `신청기간` 기준으로 오늘이 마감일 이후
  - `진행상태`가 `미진행` 또는 `종료`
- 실행 시 시트 세팅 후 한 번 호출되어 기존 행의 `숨김여부`를 보정한다.

## 4. 상태 변경 시 숨김여부 재계산

- `update_notice_status()`의 필수 컬럼에 `접수상태`를 포함했다.
- 진행상태를 변경할 때 `접수상태 + 진행상태` 기준으로 `숨김여부`를 다시 계산한다.

## 5. 기업마당 이후 멈춤 추적

- 기업마당 수집 후 Selenium 드라이버 생성 단계에서 멈추는지 확인할 수 있도록 로그를 추가했다.
- `setup_driver()` 내부 로그:
  - `ChromeDriverManager install 시작/완료`
  - `webdriver.Chrome 실행 시작/완료`
  - `Network.enable 시작/완료`
  - 다운로드 경로 설정 시작/완료
- `run()`에서 드라이버 생성 실패 시 전체 프로그램이 중단되지 않도록 `driver = None`으로 처리한다.

## 6. IRIS/스마트공장 실패 격리

- Selenium 드라이버 생성에 실패하면 IRIS와 스마트공장 수집을 건너뛰고, 기업마당 결과 저장 및 로그 처리는 계속 진행하도록 했다.
- 드라이버가 정상 생성된 경우에만 IRIS와 스마트공장 수집을 실행한다.
- IRIS/스마트공장 호출 직전 로그를 추가해 어느 단계에서 멈추는지 확인할 수 있게 했다.

## 7. 현재 이어서 반영한 작업

- `setup_driver()`에 세부 진행 로그를 추가했다.
- `ChromeDriverManager().install()` 결과를 `driver_path` 변수로 분리해 install 단계와 Chrome 실행 단계를 구분했다.
- `run()`에서 `driver`가 있을 때만 IRIS/스마트공장을 호출하도록 변경했다.
- `driver`가 없으면 `[Selenium] 드라이버 생성 실패로 IRIS/스마트공장 수집 생략` 로그를 남긴다.

## 9. IRIS/스마트공장 상세 파싱 보강

- 표 형태가 아니라 카드형 상세 화면에서 `공고일`, `마감일`, `접수 기간`, `접수 상태`, `수행기관`, `지원 대상`, `지원 내용`, `접수 방법`, `문의처`처럼 라벨과 값이 줄 단위로 분리된 구조를 읽도록 공통 라벨 파서를 추가했다.
- IRIS 상세 파서가 `공고일/접수기간/마감일/문의처/지원대상/지원내용`을 상세 화면 라벨 값에서 우선 추출하도록 변경했다.
- IRIS 목록에서 공고일을 못 읽는 경우에도 바로 제외하지 않고 상세페이지에 진입해 공고일을 다시 확인하도록 수정했다.
- 스마트공장 상세 파서가 `tr/th/td` 표뿐 아니라 카드형 텍스트에서도 주요 값을 채우도록 변경했다.
- 스마트공장 상세에서 추출한 `공고일자`, `접수상태`, `수행기관`을 기존 목록 파싱 결과에 병합하도록 수정했다.

## 10. 마감 공고 숨김 보강 및 기업마당 미리보기 확인

- `접수상태`에 `마감` 또는 `종료`가 포함되면 숨김 대상으로 판단하는 `is_closed_receipt_status()`를 추가했다.
- 신규 row 생성 시 숨김여부를 계산하고, 신규 저장 직후에도 `refresh_hidden_status_for_existing_notices()`를 다시 실행해 마감 공고가 보이는 문제를 방어했다.
- `get_active_notices()`에서도 `숨김여부 = Y`뿐 아니라 `접수상태 = 마감/종료` 공고를 한 번 더 제외하도록 보강했다.
- 기업마당 원문 페이지는 응답 헤더에 `X-Frame-Options: DENY`가 있어 Google Apps Script iframe 미리보기에서 직접 표시할 수 없다.
- 구현 가능한 대안은 `새 탭에서 열기`, 시트에 저장된 상세정보/첨부파일 렌더링, 또는 Apps Script 서버단 `UrlFetchApp`으로 원문 HTML을 가져와 필요한 본문만 별도 HTML로 재구성하는 방식이다.

## 11. 필터탈락공고 비고 형식 통일

- `format_filter_drop_note()`를 추가해 필터탈락공고 `비고`를 `원문링크: URL | ... | 출처 필터탈락` 형식으로 통일했다.
- 기존 비고에 이미 `원문링크:`가 있으면 중복으로 넣지 않는다.
- 상세링크가 있는 경우 비고 첫 부분에도 같은 링크를 `원문링크:`로 표시한다.
- IRIS 상세 진입 전 필터탈락도 `IRIS_URL`을 상세링크로 넣어 비고에 원문 링크가 비어 있지 않도록 수정했다.
- 필터탈락 중복키는 `상세링크`만 보지 않고 `비고` 안의 `원문링크`도 함께 기준으로 사용한다.

## 15. 크롤링 결과 파싱 이상 점검 및 스마트공장 파서 보강

- 구글시트 `신규공고` 22건을 점검했다.
- 기업마당 행은 주요 컬럼이 정상적으로 채워졌고, 필터탈락공고 비고도 `원문링크:` 형식으로 저장됐다.

- `smart_factory_guess_agency()`를 추가해 `수행기관/전문기관/주관기관` 컬럼, 제목의 `[기관명]`, 공고번호 문구에서 수행기관을 추정하도록 보강했다.

- 스마트공장 비고 병합 시 같은 공고번호가 중복으로 들어가지 않도록 `smart_factory_merge_note_parts()`를 추가했다.

## 16. Cross-site duplicate skip before detail crawling

- Added a runtime cross-site title key set based on the existing `수집이력` sheet.
- After Bizinfo collection, newly collected Bizinfo notice titles are added to the runtime duplicate set before IRIS and Smart Factory crawling starts.
- IRIS now skips notices before opening detail pages when the title already exists in the cross-site title key set.
- Smart Factory now skips notices before relevance filtering and detail page crawling when the title already exists in the cross-site title key set.
- The existing save-time duplicate removal remains in place as a final safety check.

## 17. Collection error log review and fixes

- Checked the `수집오류로그` sheet and found the actual crawler failure was a Windows console `cp949` encoding error while printing a Smart Factory notice title containing `∙`.
- Configured `sys.stdout` and `sys.stderr` to use UTF-8 with replacement handling so console logging cannot stop crawling on unsupported characters.
- Adjusted empty header handling so newly created blank sheets get headers without recording a header mismatch as an error.
- Verified runtime import and a test print containing `∙` both complete successfully.

## 18. Sheet parsing review and Smart Factory parser fixes

- Reviewed the latest `신규공고` sheet and found the suspicious parsing rows were concentrated in Smart Factory notices.
- Smart Factory `소관부처` was blank, so the parser now fills `중소벤처기업부` when the page does not provide a ministry.
- Prevented generic title prefixes such as `[공고]` from being used as `수행기관`; the parser now falls back to the notice number/body and correctly extracts names such as `충남테크노파크`.
- Removed Smart Factory navigation/menu text from `문의처` when no real contact signal is present.
- Added a fallback support-content extraction pass so blank `지원내용` cells can be filled from the cleaned notice body when possible.
