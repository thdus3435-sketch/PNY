# bizinfo 코드 구조화 가이드

## 현재 구조

기존 `bizinfo_datalist.py`는 백업 파일 `bizinfo_datalist_legacy.py`로 보존했습니다.

현재 실행 진입점은 `bizinfo_datalist.py`입니다.

```text
bizinfo_datalist.py
bizinfo_collector/
  __init__.py
  runtime.py
  parts/
    00_config_keywords_headers.py
    01_common.py
    02_sheets.py
    03_logging_driver_row.py
    04_bizinfo.py
    05_iris.py
    06_smart_factory.py
    07_dedupe_runner.py
```

## 파일별 역할

| 파일 | 역할 |
|---|---|
| `bizinfo_datalist.py` | 기존처럼 실행하는 작은 진입점 |
| `bizinfo_datalist_legacy.py` | 분리 전 원본 백업 |
| `bizinfo_collector/runtime.py` | 분리된 파일들을 순서대로 로드하고 `run()` 실행 |
| `00_config_keywords_headers.py` | 기본 설정, URL, 정기공고/키워드/시트 헤더 |
| `01_common.py` | 날짜, 정규화, 점수 계산, 공통 row/key 유틸 |
| `02_sheets.py` | Google Sheets 연결, 헤더 보정, 저장, 상태 변경 |
| `03_logging_driver_row.py` | 오류/필터탈락 로그, Selenium 드라이버, 최종 row 생성 |
| `04_bizinfo.py` | 기업마당 목록/상세 파싱 |
| `05_iris.py` | IRIS 목록/상세/첨부/링크 파싱 |
| `06_smart_factory.py` | 스마트공장 목록/상세/첨부/다운로드 파싱 |
| `07_dedupe_runner.py` | 신규 row 중복 제거와 메인 실행 흐름 |

## 실행 방법

기존과 동일합니다.

```bash
python bizinfo_datalist.py
```

## 이번 분리 방식

이번 작업은 기능 동작을 바꾸지 않기 위해 원본을 기능별 파일로 기계적으로 나누고, `runtime.py`가 같은 순서로 로드하는 방식입니다.

장점:

- 기존 코드 동작을 최대한 보존합니다.
- `bizinfo_datalist.py`가 짧아져 진입점이 명확해집니다.
- 이후에는 기업마당/IRIS/스마트공장 파일만 따로 열어 수정할 수 있습니다.

주의:

- 아직 완전한 Python 패키지형 리팩터링은 아닙니다.
- 분리된 part 파일들은 현재 하나의 공유 namespace로 실행됩니다.
- 다음 단계에서 공통 유틸, 설정, 시트, 사이트별 수집기를 정상 import 구조로 천천히 바꾸는 것이 좋습니다.

## 다음 단계 추천

1. `config.py`: 설정값과 헤더만 분리
2. `models.py`: row 인덱스 대신 dict/dataclass 사용
3. `sheets.py`: Google Sheets 입출력만 담당
4. `collectors/bizinfo.py`, `collectors/iris.py`, `collectors/smart_factory.py`: 사이트별 수집기
5. `runner.py`: 실행 흐름만 담당

이 순서로 가면 한 번에 크게 깨뜨리지 않고 점진적으로 구조를 개선할 수 있습니다.
